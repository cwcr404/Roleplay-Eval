## 〇、一页真相：现在为什么"不像芽衣"（沿用，没变）

现状 `SessionEngine.turn()` 把链**折叠成一次裸 LLM 调用**：

```
用户msg → [agent2_character.md(人格) + 记忆外挂区] → 一次非流式_chat → 回复
```

问题（都在会话线 = 产品线；评测线 run_eval 不受影响）：

1. **agent1(路由)、agent3(质检) 在代码里零调用点 —— 死 prompt**（除 run_eval 一行注释，全库无真实引用）。
2. **agent2_character.md 按老契约写**（预设收到 `[闲聊]`/`[攻略]` 标记）：产品线没人打标记
   → 人格卡里"攻略改写/背景带入"触发逻辑**全空转**。
3. **背景库+攻略库在产品线从不查**。`kb.retriever.build_kb()`(Guide/Lore)只在评测线被用。
4. 结果：喂给模型的 = 人格卡（标记失效没被好好触发）＋记忆外挂。背景没有、攻略检索没有、
   质检门没有 → 输出 = 套了薄人设壳的通用 LLM = **客服腔底子**。

**不是设计过时，是 Agent1 该在链上的位置被裸调用架空。** 修复 = 接回编排，不是换设计。

## 一、两条线分家（宪法级，核心裁决）

| | 产品线（chat_session / web / 给真人聊） | 评测线（run_eval · 判角色一致性） |
|---|---|---|
| 体感要求 | **快**：单轮 ≈ 1 次 LLM 调用时长 | 慢点无所谓：要评判严谨 |
| 编排 | **三合一单次流式调用** | **三 Agent 串行**（现状，不动） |
| 路由 | Agent1 收进 Agent2 prompt 前置段 | agent1 独立路由（评测可控性） |
| 质检 | Agent3 **异步**（不阻塞本轮） | agent3 同步把关（严谨） |
| 记忆 | 照旧在底跑 | 评测隔离（guard 严禁接记忆，现状） |
| 形态 | 快、有人味、边打边出 | 慢、每个 case 三种 Agent 严格走 |

**"评测慢产品快"**：评测线要的是**每一次都判得准**（三 Agent 串行保严谨）；产品线要的是**真人聊得下去**。
两条线的 Agent 缺省各配各的 prompt/模式，互不污染。

## 二、产品线链路（三合一，体感 ≈ 1 次 LLM）

```
用户消息
  → 一次流式 LLM 调用 = [Agent2 prompt 前置段内嵌路由] + 人格 + 记忆 + 可选 KB 事实
        调用内第一步：先自己在回复首行给出 [闲聊] / [攻略] 标记（结构化首行）
        然后按标记当场决定：闲聊用 V2 背景入戏演 / 攻略先查 V1 干货再以芽衣口吻讲
  → 流式返回给玩家（打字感）
  ─────────────────────────────
  Agent3 质检 = 异步，回复发出后才评：
     判决写【右面板】（可见 = 好优化：用户能看到"这轮该改什么"）
     不合格 → 记日志 + 下一轮修正；禁止同步打回循环（绝不阻塞/打断本轮）
  ─────────────────────────────
  记忆链路全程在底：书记员/L1/好感/衰减/承诺/时钟，不进推理路径，照旧
```

**一次调用如何"内嵌路由"？** 不改人格内核，改的是 **agent2 prompt 的前置段**（装配层塞一段
"开头先判标记再演"的指令）＋ agent2 user prompt 按"是否已拿攻略"给不同拼接。具体：
- system = 人格卡原文(冻结) + 记忆外挂区 + **一段"先自报标记"的前置指令**（可解析首行）。**拼装顺序钉死**：人格卡原文固定**最前**，前置指令 + 记忆外挂区在后，任何拼装不得把内容插入人格文本中间——人格是"芽衣是谁"的锚，位置都不能让它被挤散。
- **标记剥离（写死）**：`[闲聊]/[攻略]` 标记只作 engine 分叉依据，**绝不进玩家可见流**。流式下首块 chunk 就含标记，engine 必须先缓冲首行、用正则吃出标记并**从可见流里剥掉**，确认无残留标记后才放行后续 chunk——这是「先解析再放行」两段式，比"读到即转发"高一档，施工难度按此估。
- 攻略命中判定：Agent2 自己首行吐 `[攻略]` → engine 读到/流到时**触发攻略库查询**再喂回，
  或更简单：首行标记后正文就是攻略改写。**mock 时以"首行可被引擎正则解析出 [闲聊]/[攻略]"
  为准**（防自由文本、防不可控）。
- **缺省分支（写死）**：首行解析失败（模型自由发挥/空行/emoji 开头/吐不出可解析标记）→ 运行时**默认按 `[闲聊]` 走**，不重试、不阻塞、记一条日志（含原始首行原文）。绝不现场发挥——缺省不写死，施工就会现场发挥，那正是范围膨胀的入口。工程上：解析失败按 [闲聊] 处理 ≠ 自由文本放行，只走人味闲聊路径，不进攻略库强灌。

> 注：此处"一次调用内自报标记再分叉"对 LLM 有一定自我约束要求——它是**产品线的取舍**：
> 用"单调用 + 流式"换体感，接受路由部分交给模型内部控制；评测线才用独立 agent1 做严谨路由。

## 三、Agent3 = 异步质检（产品线），不阻塞回放

- **位置**：产品线里 agent3 **退出主回复延迟链**，回复先流式给玩家，审核后置。
- **判决落点**：web 右/下**面板**展示判决（可见=好优化，用户知道芽衣哪句该改）；
  不合格 → 记日志 + 记入下一轮修正上下文（下轮 agent2 会知道上轮被挑的毛病），
  **禁止同步打回循环**（绝不因为质检不过让玩家再等一轮重生成）。
- **注入纪律（洞3 · 写死，防投毒面）**：下一轮注入**只准描述性、禁止指令性**。agent3 判决是
  LLM 自由文本，若整段直接进 agent2 是投毒面——质检被对抗输入带偏，等于借 Inspector 之手改芽衣人格。
  改法：判决落账本走**固定格式描述性通道**，外套固定壳「上一轮质检意见：X」，**壳外内容一律不进 prompt**。
  这是文字入注原始纪律（人味入注/规则入注都要求纯描述、禁指令）的严格执行。
- **时序注入副作用警惕（洞3b · 防渐进式 OOC）**：上轮被挑毛病→下轮自我修正→连轮积累会把芽衣慢慢
  改写成讨好质检。零八二七焊的四柱「抗渐进式 OOC」正是防这个。故加**频次闸**：连续修正 ≤N 轮
  （建议 N=3），超闸后不再注入只记日志——产品线求快，不等于质检意见无限量灌进人格。
- CLI/无面板处：不合格记日志即可，日志是肉眼可查的"质检在动"证据。
- **防"异步=没人看"坑**：agent3 必须真被调、真产出判决（见验收）——没面板也得写日志。
- 成本：agent3 每轮 ~1 次短 LLM（几十字判决），异步跑不挡首字。demo 可每 N 轮跑一次降本。

## 五、Engine 形态变化（改动最小化）

### 现骨干（保留）
`SessionEngine.turn()` / `_system_for_turn()`(人格+记忆) / 记忆链路 / 时钟 / 书记员 —— 骨架好。

### 产品线改法
1. `turn()` 主回复改**流式出口**：utils/api 加 streaming（SSE 或逐块回调），agent2 首字尽快出。
2. agent2 prompt **前置段塞"先自报 [闲聊]/[攻略] 标记再演"指令**（人格原文不动，只加装配段）。
3. 读到 `[攻略]` → engine 触发 guide.query 把干货续喂/注入下一段；读到 `[闲聊]` 且能猜主题 →
   lore.query。首行标记由 engine 正则解析并**从可见流剥离**（玩家侧永不见标记文本）。
4. **agent3 拆成异步**：回复已回玩家后，单独一程跑质检 → 判决写面板 + 日志 + 记入下轮上下文。
5. 记忆/书记员/历史/时钟：**一步不动**。

### 评测线
`run_eval` **完全不动**：agent1 独立路由 + agent2 + agent3 串行，评测隔离照旧。

## 七、验收（按 00:19 拍板收紧）

迟旭拍板验收更新：**产品线 web 会话线断言 =「Agent2 单次调用产出 + Agent3 异步判决落面板」；
防架空断言从"防串行空转"改成"防同步化回退"。**

新增验收（打进 `session/acceptance_probe.py`，注入计数桩 + 假流式）：

1. **产品线主回复 = 单次调用产出**：注入假 LLM 桩返回"`[闲聊]` + 正文"→ 断言 agent2 主回复段
   **恰好 1 次** LLM 调用、reply 即该次产出（无 agent3 阻塞重生成、无同步打回循环）。
2. **路由标记可解析且分叉**：桩返回 `[攻略]` 时 → 断言触发了 guide.query、干货进了正文；
   `[闲聊]` → 视主题查 lore（或省）。首行标记被 engine 正则吃掉，不自由文本放行。
   **剥离断言（洞1）**：玩家最终可见流里**不含**任何 `[闲聊]`/`[攻略]` 标记文本——断言拿
   engine 输出的玩家侧全文搜标记子串 = 0 命中（流式桩模拟分块到达，验证首行先缓冲剥离再放行，
   而非"读到即转发"）。
2b. **首行解析失败兜底（洞2）**：注入假 LLM 桩返回"开头无标记的自由文本 / emoji / 空行引子"
   → 断言 engine **不抛错、不重试、不阻塞**，按 `[闲聊]` 缺省路径产出；且日志里记了本次缺省分支
   （含原始首行）。反证：任何实现若把解析失败当异常抛/卡死/自由放行进攻略库 → 本断言红。
3. **Agent3 是异步的**：断言 agent3 不在"主回复返回路径"里被同步等待（用假延迟桩验：主回复
   先到、判决后到），且**判决落了面板/日志**（防"异步=没跑"）。防回溯断言：任何实现若把
   agent3 塞回同步打回 → 本断言红。
4. **记忆链不受扰**：同轮走完，书记员/账本/好感数字与重构前一致；四套离线回归 + 五条验收仍绿。
5. **真 web 手感（真 LLM，手动冒烟，迟旭目测）**：聊一句闲聊+一句攻略——体感首字快、
   全程打字感、攻略说人话不念稿、面板能看到异步质检判决。

## 八、已知取舍与风险（诚实写）

- **内嵌路由的可靠性**：产品线把路由交给模型自报首行，可能标错。**错标不对称**——
  `[攻略]` 错标成 `[闲聊]` 只缺干货、无害（人味还在）；**`[闲聊]` 错标成 `[攻略]` 会把干货
  强灌进闲聊，伤人味**——这个是冒烟重点盯的方向。若频发，兜底 = 攻略分叉加**轻量关键词确认**
  （命中攻略特征词才认 [攻略]），**不是**加回 agent1——别让补丁把三合一拆回去（拆回 = 每轮
  多一次调用，毁体感）。评测线仍用独立 agent1 保严谨，两线分家正是为此。
- **流式 + 内嵌路由顺序**：路由首行要先出、正文后出，技术上是可行的流式次序（首 token 即标记)，
  但要求 api 逐块回调能拿到"首行再决定后续拼接"——施工时确认 DeepSeek 流式接口细节。
- **agent3 异步打盹**：判了不重写/判错，demo 接受（记日志可查）；够精致再叠规则门。
- **人格常量风险**：任何"顺手改 agent2_character.md"都可能动"芽衣是谁"。规则：**人格原文冻结，
  装配只加前置段/记忆，不动角色内核源文本的那段人格描写**。
- **成本**：产品线单轮 = 1 次流式主回复(可长) + 1 次异步质检(短) + 书记员(短) ≈ 可接受；
  攻略长回复成本主要花在"干货改写"，值得。

1. 先 utils/api 加**流式通道**（假流式可先绕过真流式做桩）；engine 主回复接流式。验首字快。
