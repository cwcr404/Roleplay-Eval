## Why:这个项目为什么这么设计

复杂度不在代码量,在**判断**。下面三条不是立场声明,是可被审查的施工结果:
两条纪律、一组验证状态、一处明示边界。

### 纪律牌一:规则往「宪法」写,不往「手册」堆

> **规则越写越多,必然互相打架;所以把不可动摇的少数写成宪法,把可调的多数做成参数。**

角色 AI 的典型失败是「补丁地狱」:每出一个 OOC 就加一条规则,两百轮后规则互相
冲突,模型被塑形成讨好型人格。本项目的解法是分层——**宪法级接口永不改,可调数值
全进 params**:

- 记忆账本接口(`kb/memory/service.py`)是宪法:调用方只依赖契约,内部实现可换。
- 好感衰减系数、阈值等**数值全进 `kb/relation/params.py`**,与宪法分离。
- 人格内核源文本**冻结**:关系分数只调「怎么对你」,调不到「你是谁」。
  任何拼装都不得把内容插进人格文本中间(`session/engine.py` 拼装顺序钉死)。

**判据**:数值改动 = 改配置,宪法改动 = 改代码 + 过 review——**两者的改动路径本身
不同**,不需要额外检查拦住谁。新人接手时一眼能分清哪些能动、哪些碰了就是事故。

### 纪律牌二:结构消灭 > 检测防范

> **能在结构上让问题不发生,就不要用运行时检测去接它。**

- **首行路由标记**:不让标记混进玩家可见流**再过滤**,而是「先解析再放行」——
  引擎缓冲首行、剥掉标记、确认无残留才放行正文(`session/routing.py`)。
- **注入纪律**:Agent3 质检意见**只准描述性、禁止指令性**,且由代码层丢弃壳外
  一切指令尾注(`session/async_quality.py`)——不是靠模型「自觉不照做」。
- **计量权威**:L2 预算规格以**字符**表述(`kb/memory/distill.py::CHAR_BUDGET`),
  enforce 侧**执行同一单位、同一数字**——规格数字恒为唯一权威,不存在第二套换算
  标准。确定性的截断不依赖 tokenizer,单进程零依赖即可复现。

**判据**:出问题时先问「能不能让它压根不发生」,而不是「加个检查拦住它」。
检查会漏、会漂移、会被绕过;结构不会。

### 验证状态:这两条纪律挨过实战

纯数字,零形容词。

- **真模型端到端**:DeepSeek 真实 API 跑 **14 轮**对话,事件抽取层(「事件抽取器/
  书记员」,把对话抽成结构化 L1 事件的独立 Agent)抽出 **8 条** L1 事件。
- **真实蒸馏留档**:L2 蒸馏触发 **3 次**,末态 **8/8 事件全部吃满**;留档
  `session/_calib_archive/`。(此前的一轮校准暴露了读路径缓存覆盖 bug——规则回退
  会冒充真实蒸馏、把计数虚抬到 4 次;修好后计数归真。这是修正,不是退化。)
- **回归**:离线全量回归 **12/12** 全绿(用例 A–E + 三套自检 + 路由 + 标记中途可观测
  + 蒸馏 + 回放一致性)。

### 已知边界:哪一处还没打

过度矫正防线的**机制行为**已在离线环境验证钉死;它在真实对话分布下多久触发一次、
触发面多大,**尚无观测数据**。这个空缺是**有意保留的验证边界**——真实触发面只能由
公网部署后的首批真实对话校准,用模拟数据填它等于自欺。部署后以两个仪表
(`qc_injection_rate`、`marker_mid_rate`)的首批真实读数收口。
