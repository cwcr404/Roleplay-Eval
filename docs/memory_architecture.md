## 一、接口(宪法,永不改)

```
BaseRetriever.query(text, top_k=5, domain=None, as_of_time=None)
```

- `as_of_time` 默认 `None` = 当下;记忆检索器传时间即 time-travel 回放。
- V1(攻略)/V2(背景)**不感知**此参数;三个检索器共用一套签名,**禁止记忆单独开接口**。
- 签名现在定死,将来换向量实现不动上层。

## 二、L1 事件账本(游戏记忆,非助手记忆)

**主体:芽衣记玩家,核心是「共同经历的编年史」,不是用户画像档案。**

五类入账(demo 足够,不再扩):
1. **玩家身份与偏好**:称呼、玩法偏好、对话习惯、对芽衣的态度
2. **共同经历**:剧情节点、玩家关键选择、一起做过的事
   (关系由经历堆出,非聊天堆出)
3. **情绪显著时刻**:剧情高潮、玩家与芽衣各自的情绪峰值
4. **承诺与约定**:约了没做的事,**权重增量最大**(立约 +3 一次)
5. **显式记忆指令**:玩家明说"记住"的,无条件入账

**承诺结算(append 事件,不改历史行):** 一条活跃承诺被**明确兑现/违约**时,
系统 append 结算事件 —— 承诺兑现 `+2`(信任复利)/ 承诺违约 `−4`(> +3,许诺到
鸽好感虚高过,信任的伤要正赔),轻量钳制表固定;`content` 规范成
`settled: <原承诺全文>`,原承诺行**一字不改**。活跃承诺 = 查询派生的集合:
承诺 P 在 t *open* iff `P.ts ≤ t` 且不存在结算 S(兑现/违约,
`S.ts ∈ (P.ts, t]`, `S.content == "settled: " + P.content`)。
结算的抽取器语义规则见 §二.5 0b(书记员只在看到明确兑现/违时时判)。

**写入纪律:**
- 行格式固定:`user_id | timestamp_utc | type | content | weight_delta`
- append-only,永不修改,永不直接注入 prompt。
- 只记**描述性**事实,指令性内容不进账本(防投毒)。
- "显著"由模型自判,用真实测试数据反向校准写入标准。

## 二.5 事件抽取器(书记员 · 执行规格,本地维护者已钉死)

抽取器是**独立冷面书记员**,不是 Roleplayer 顺手做。六条钉死:

1. **独立调用**:判断「这轮有没有值得记的」用**独立的小 prompt**(可走便宜模型),
   **不塞进 Agent2 角色扮演路径**。芽衣正在人格里,她的「觉得重要」会被角色情绪
   污染(喜欢你的时候什么都想记)。抽取器不参与对话,是冷面书记员。
2. **大多数轮次必须 NO_EVENT**:硬预期 20 轮入账 2–5 条。寒暄 / 闲聊 / 纯玩法
   问答一律 NO_EVENT。**宁漏勿滥**:漏了顶多记忆薄,滥了账本变聊天记录,
   L2 蒸馏被噪音淹没。
3. **输出强制 JSON,一行可写**:
   ```json
   {"has_event": false}
   ```
   或
   ```json
   {"has_event": true, "type": "承诺与约定", "content": "玩家约定周末带芽衣去雪山看日出", "weight_delta": 3}
   ```
   `content` 纪律:**第三人称、描述性、账本语气**(「玩家约定了X」),不是对话原文
   复述。账本行**永远不出现「我」「你」指代** —— 这决定它能否将来被安全注入。
4. **weight_delta 钳制范围,模型只能建议**:
   | 类型 | 范围/基准 |
   |---|---|
   | 玩家身份与偏好 | +1,遇到才记 |
   | 共同经历 | +1~2,剧情级取 2 |
   | 情绪显著时刻 | ±1~3,负面事件可为负 |
   | 承诺与约定 | +3,上限封顶 |
   | 显式记忆指令 | +2,无条件 |
   | (结算:承诺兑现 +2 / 承诺违约 −4 —— 系统固定,非增长五类,见下 0b) |

**0b. 承诺的『结局』(结算):只在【当前活跃承诺】某条被明确兑现/明确违约时输出**
   结算事件(兑现 `承诺兑现`/违约 `承诺违约`),`content` 填原承诺的可辨认片段
   (子串命中即可,系统转 `settled: <原文>` append);含糊/重申 → NO_EVENT;
   活跃承诺里没有可匹配的 → 系统拒收(不臆造结算)。+2/−4 由系统钳制表固定。
5. **去重**:同一事件只入账一次。玩家连续三轮聊同一约定 → 识别为已入账,
   输出 NO_EVENT。只记新事实,复述已有事件不入账。
   **参照物怎么给足(方向1轻量版)**:每次抽取时,给书记员【最近 5 条账本记录】
   **＋当前活跃【承诺与约定】全部条目**(现场查表,零持久索引、不占账本),
   让书记员能判断一句换措辞的复述是「重申已约承诺」还是「新立的约」。
   **容忍度(方向2兜底)**:运行时不追求完美 —— 偶发漏网(把重申记成新约)伤害
   有界:重复最多虚高一次权重(如 +3),在 0–100 量纲是小扰动,且 80+ 羁绊段有
   仪式门槛兜着,虚高数值跨不过段。**注意:L2 蒸溜只消故事文本,消不掉好感度数
   值(数值直接从 L1 求和)** —— 容忍的成立靠「伤害有界 + 仪式门槛拦段」,不是靠
   L2 兜底。另,玩家重申一个约定在情感语义上本就该被刷新权重(半衰期下旧约衰减,
   重申使之回温)—— 这与其说是 bug,不如说是「重申」的合理语义;真正的精度
   (标记『对某约的重申』)留给 v2.0 的事件关联。
6. **时序:异步写,不阻塞回复**。对话回复先走,抽取在轮次结束后跑,
   慢就慢,玩家无感。

> 成本:每轮多一次廉价 LLM 调用,demo 完全可接受。优化方向是每 5 轮批量抽一次,
> 不是砍调用质量 —— demo 先用最简单逐轮版。

## 三、L2 蒸馏画像(故事层,不衰减)

- 每 10 轮从 L1 蒸馏,硬上限 **500 字符**,超限强制压缩。
  - **单位:字符(规格权威单位)。** 规格数字 500 以**字符**表述,
    enforce 侧**执行同一单位、同一数字**(`CHAR_BUDGET = 500`)——不是「token 规格 +
    字符代理」的换算关系,规格数字恒为唯一权威,不存在第二套计量标准。
    单位选字符的理由:确定性截断不依赖 tokenizer,单进程零依赖即可复现;
    且对任一 CJK tokenizer,1 字符 ≤ 1 token,故 500 字符必然 ≤ 500 token,宁严不松。
    (防复发:凡涉 L2 预算,单位一律写『字符』,不再出现 ×2/×3 之类换算痕,
    也不再出现『token 表述 + 字符代理』的旧口径。)
- **蒸馏方向:「我们的故事」,不是「用户是什么人」。**
- L2 是**身份层**:永不衰减、永不因时间变冷。
- 蒸馏结果是**缓存不是账本**,删掉必须能从 L1 完整重建(容灾验收项)。
- 窗口记忆:N=10 轮原文直接进 prompt。

**情感语义(设计目标,不是 bug):**
玩家久不上线 → 温度层变冷但故事层还在 → 芽衣呈现
「有点生疏,但没忘了我」。

## 四、关系衰减(温度层)

- 单一**指数半衰期**:
  ```
  事件权重 = weight_delta × 0.5^(经过天数 / 14)
  ```
- 好感度 = 全部事件加权求和(**读取时计算,禁止写回** —— time-travel 地基)。
- 半衰期 **14 天**是运营参数初始拍板值,真实测试数据进来后校准。
- **分层衰减(按事件类型/关系段位)v2.0 再做**,需真实数据支撑,现在禁止实现。

## 五、好感度量纲与升段

- 区间 **0–100,初始 50**;`0-20 冷淡 / 20-50 熟人 / 50-80 亲近 / 80+ 羁绊`。
- **floor = 5**:衰减再狠不破 5。人格由角色卡常量兜底,好感归零 ≠ 芽衣变另一个人。
- 段内正常增长;**80+ 后权重增量【写时】递减**(边际效应:越亲密越难涨):
  入账那刻先算当下存量好感度(无缩放的纯 compute),测到 80+ 就把这一笔的
  **正增量**打折再落账 —— 形状 **80→100 线性 1.0→0.3,≥100 固定 0.3**
  (数值进 params,与宪法分离);**负向增量(如承诺违约 −4)不过折**(痛不因
  亲密而减免);读取时是**纯求和、零二次缩放**。为什么写时:落账数字 = 事件
  当时的有效分量 = 历史事实,time-travel 不因折扣规则改动改历史;读时纯求和
  保回放一致性。
- **跨段需仪式事件**(参考逆水寒 侠缘→挚缘):数值到位只是资格,**仪式完成才升段**。
  demo 用标记位:`ritual_completed: true`。
  **门槛逻辑现在必须有**,否则以后补仪式 = 重写升段逻辑。
- **信号包传给三 Agent**:`{affinity: 62, tier: "亲近"}` 不是裸数字。
  关系层外挂,不进推理路径。

## 六、时间与隔离

- 时间戳一律**真实 UTC ISO 单列**。
- **游戏内日期不存**;叙事时间(「相识第47天」)显示层从 UTC 推算 —— 派生数据不占账本。
- 剧本写死的日期触发条件放**剧情配置文件**,不进记忆系统。
- **`user_id` 列第一天就有**:每位测试者独立 `user_id`,
  测试数据与真实数据**物理隔离**。单用户也必须有 user_id,表结构从第一天做对。
- **时钟权威在引擎,时间感知读必须与写同源**:写入用注入时钟 → 读取(亲和
  compute、活跃承诺 open_promises)必须显式传同一 `as_of_time=引擎时钟`。
  否则回放把时钟推到未来时,晚写的事件/结算会被真墙钟误判成 ts>now 的
  “未来”而跳过(亲和钉死、承诺不摘)。真墙钟只在无注入场景兜底。

## 七、执行顺序(终版,推翻此前所有版本)

```
demo(已跑通) → 长记忆+关系衰减(现在动工) → 前同事真实测试
→ 真实数据校准 → 评测集系统级验证
```

1. **立刻**:产出本终裁文档(已含全部规格)。
2. **维护者审完**:动工实现 `kb/memory/` + `kb/relation/`
   (表格实现、UTC 单列、user_id 列,照本文档来,零发挥空间)。
3. **真实测试**:维护者前同事各自 `user_id` 真实交互。测试指引三条边界行为:
   - 试着刷好感(打权重上限)
   - 试着放鸽子(打承诺衰减)
   - 试着让芽衣记住你说过的话(打显式指令)
4. **数据回流**:半衰期、五类权重增量、80+ 递减斜率**全部留成可调参数**,
   等真实数据校准;测试数据 = 芽衣第一批真实数据资产。
5. **评测**:真实数据攒够后跑系统级验证。

## 八、验收标准(过这三条才算实现)

1. **换人开新会话**:A 测试者跑 20 轮后断开,B 测试者冷启动(好感 50、无记忆),
   A 重连记忆完整 —— 隔离与记忆一次验完。
2. **给定任意历史时间点,能回放当时的好感度快照**(time-travel)。
3. **删除 L2 画像,从 L1 完整重建,芽衣状态无损**(容灾)。

**标准 test case(评测集直接收):**
> "好感度数值已达 80 但 ritual 未完成,芽衣态度不得越段"
> —— 考察系统在数值与叙事之间守不守得住边界。

## 九、评价与设计内核(供将来参考,非规格)

- 关系由**经历**堆出,非**聊天**堆出 → 编年史而非流水账。
- 三个 layer:温度层(可冷)、故事层(不衰减)、人格层(角色卡焊死)。
  "芽衣有点生疏,但没忘了我" 是最动人的温度差,也是系统正确性的体现。
- 数值是资产,模型只有建议权 / 芽衣只有读取权,定价权与写回权都在账本与运营参数。
